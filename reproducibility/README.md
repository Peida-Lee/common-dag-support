# Final reproducibility package

This package accompanies *Common-DAG Support from Targeted Covariance Changes under Confounding*, an ICML 2027 draft.

## Scientific scope

The package provides the final specification and results for the paper's experiments.

| Experiment | Declared design |
| --- | --- |
| Gaussian power | Four templates, four gaps, four sample budgets and 32 replicates, giving 2048 conditions |
| Joint polynomial reference | The same 2048 covariance conditions and confidence constraints |
| Connected population support | Two downstream structures, three sizes, four templates and four gaps, giving 96 conditions |
| Standard light | Eleven acquisitions and 20000 measured rows |
| Wind | Twenty-eight acquisitions and 23449 measured rows |
| Camera | Three 4096-row prefixes and fifteen numeric coordinates |
| Optical device | Thirteen 1000-row acquisitions with a fixed linear basis |

The real-data experiments evaluate fixed final estimators on the public acquisitions used for their development. The standard-light, wind and camera scores use the source's listed-positive working reference, with other physical labels treated as unknown. The optical scores evaluate source-defined pixel-to-sensor slots. The paper and `specifications/reference_labels.json` define these objects.

## Frozen specification

`freeze.json` records the final algorithms, final input fingerprints, model definitions, experiment plans, seed rules, installed package versions and freeze identifier. It was written before the delivered experimental replay. `execution_manifest.json` records the delivered final cases and their execution times. `derived_input_manifest.json` describes the deterministic standardized CSVs and native WVM configurations generated by the frozen preprocessing code.

`src` contains the scientific functions used in the final analyses. `verification` contains separate rational and symbolic checks. `vendor` contains the retained author sources for MuDo-CoM and WVM. `environment` contains the Python requirements and Julia project lock files. `inputs` contains the public numeric inputs and calibration banks.

The supplied outputs include final sample scatters, primitive random draws, graphs, P values, fitted baseline parameters, certificates and paper tables. A fresh replay generates Monte Carlo reference blocks from the fixed seed rules.

## Environment

The delivered replay used Linux, Python 3.11.11, PyTorch 2.5.1 with CUDA 12.1, a single NVIDIA L40 and Julia 1.6.7. Exact Python versions are in `environment/python_requirements.txt`. The Julia `Project.toml` and `Manifest.toml` pin the native WVM dependencies.

The queue uses distinct physical cores and one BLAS/OpenMP thread per worker. Its server configuration reserves 128 GiB of available memory and allows up to 192 simulation workers, 64 CPU baseline workers and four GPU baseline workers. Individual task errors are recorded while the remaining queue continues.

Install the Python environment with the following commands.

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r environment/python_requirements.txt --extra-index-url https://download.pytorch.org/whl/cu121
```

Instantiate the pinned Julia project with Julia 1.6.7. An existing compatible personal depot can be supplied through `DAG_JULIA_DEPOT`.

```bash
export DAG_JULIA=/path/to/julia-1.6.7/bin/julia
export DAG_JULIA_DEPOT=/path/to/julia_depot
JULIA_DEPOT_PATH="$DAG_JULIA_DEPOT" "$DAG_JULIA" --project=environment/WVM --startup-file=no -e 'using Pkg; Pkg.instantiate()'
```

## Full replay

Create a new execution directory to regenerate the experiments from the released frozen inputs.

```bash
.venv/bin/python create_fresh_replay376_v1.py /absolute/path/final_replay
export DAG_PYTHON=/absolute/path/to/.venv/bin/python
bash /absolute/path/final_replay/reproduce.sh
```

The driver runs the declared stages and produces the final graphs, verification outputs, tables and power figure. A task receipt with `status` equal to `completed` supports recovery within that fresh run. Resolve recorded task errors before interpreting the final tables.

For a stage-specific replay, use the following entry point inside the fresh execution directory.

```bash
"$DAG_PYTHON" run_final376_v1.py power
"$DAG_PYTHON" verify_final376_v1.py power
"$DAG_PYTHON" summarize_final376_v1.py
```

`final_results.json` reports an incomplete status until every declared scientific result is available. It retains all conditions in the declared design. The reported optical estimator is the union of its fixed MuDo-CoM graph and the linear group-F additions.

## Calibration and interpretation

The Gaussian procedure uses four fixed, independently generated M=1023 reference banks and the allocations stated in the paper. Standard light uses 32767 synchronized assignment draws. Camera uses 32767 full source-trajectory draws, followed by the stated three-condition combination. Wind uses exact conditional KS upper tails. Optical group tests report original P values at the nine-group allocation.

Native WVM uses its authors' bootstrap moment estimation and fitted Gamma calibration with B=200. The configuration files retain its primary and secondary levels, response columns, source groups and seeds.

The rational and symbolic verification routines share primitive inputs and interval conventions with the main computation. Their outputs document source regeneration, covariance enclosures, Fieller coverage, accepted joint coefficients, exclusion certificates and connected-model inverses.

## All-slot reference

The paper also reports a deterministic reference that selects every relation in each declared domain. Its code uses the frozen domains and listed-positive labels, together with the delivered optical estimator counts for the precision and recall comparison.

Run the following command inside the package directory to regenerate this analytical comparison.

~~~bash
python evaluate_density_reference378_v1.py . --output outputs/final_tables/density_reference_results378_v1.json
~~~

The domain-only prediction rule and input fingerprints are recorded in density_reference_definition378_v1.json. Its score identities are in theory_density_reference378_v1.md.

## Root-target compatibility verification

The revised paper adds Proposition 2 and Appendix K.6 on root-target designs. The deterministic 24-case rational verification accompanies the existing final experiments. Its targeted and untargeted queries and general acyclic parameterization are recorded in supplement382_v1.json.

```bash
python verification/check_root_target_design381_v1.py --output outputs/verification/root_target_design381_v1.json --workers 8
```
